# Статус проекта PlatformLove

Обновлено: 2026-09-15

## Стек

- **Фронтенд**: React 19 + Vite 8 + Tailwind 4, React Router 7, Capacitor 8 (Android)
- **Бэкенд**: Node.js + Express 5, JWT, bcryptjs, multer, nodemailer
- **БД**: SQLite (`server/database.sqlite`), идемпотентная миграция `server/src/db/migrate.js`,
  демо-данные `server/scripts/seed.js`

## Команды

| Что | Команда |
| --- | --- |
| Фронтенд (dev) | `npm run dev` → порт **5175** |
| Сборка веба | `npm run build` |
| Линт | `npm run lint` |
| Бэкенд (dev) | `cd server && npm run dev` → порт **3001** |
| Миграция + демо-данные | `cd server && npm run db:init` / `node scripts/seed.js` |
| Синхронизация Android | `npx cap sync android` |

Vite проксирует `/api` и `/uploads` на `http://localhost:3001`, поэтому во фронтенде
используются относительные пути.

## Авторизация

### Исправленный корневой баг

`src/api.js` кэшировал токен в конструкторе синглтона. После входа токен попадал в `localStorage`,
но экземпляр `api` продолжал слать запросы **без** `Authorization`, и все экраны после логина
работали как анонимные. Теперь токен читается актуально через геттеры `authToken` /
`authAdminToken` на каждый запрос.

Проверено headless-скриптом: запрос до логина идёт без заголовка, после логина заголовок
присутствует, `/api/auth/me` возвращает того же пользователя.

### Маршруты входа

| Сценарий | Поведение |
| --- | --- |
| Логин + пароль, PIN не задан | `/menu`, если анкета заполнена; иначе `/profile` |
| Логин + пароль, PIN задан | шаг 2 — ввод PIN, затем `/menu` |
| Регистрация | токен сохраняется, переход на `/profile` (анкета) |
| Установка PIN (`/set-pin`) | после сохранения → `/menu`; PIN опционален и не блокирует вход |
| Вход по СМС (`/verify`) | `send-code` → `verify-code` → `/profile` для новых, `/menu` для существующих |
| Выход | `api.logout()` очищает токен |

PIN больше не является обязательным барьером: раньше вход без PIN отправлял пользователя
в мастер «создай PIN → анкета», и в приложение он не попадал.

### Защита маршрутов

`RequireAuth` (layout-роут в `src/App.jsx`) разворачивает на `/` все экраны, требующие токена:
`/profile`, `/questions`, `/menu`, `/swipe`, `/wall`, `/match`, `/likes`, `/fans`,
`/notifications`, `/messages`, `/feed`, `/friends`, `/user-profile`, `/chat/:id`,
`/settings`, `/subscription`, `/blacklist`.

`RootGate` на `/`: онбординг → (есть токен ? `/menu` : форма входа).

### SMS-эндпоинты

Реализованы в `server/src/routes/auth.js` на существующей таблице `verification_codes`
(`id`, `phone`, `code`, `attempts`, `expires_at`, `verified`, `created_at`):

- `POST /api/auth/send-code` — генерирует 4-значный код, срок жизни 5 минут,
  инвалидирует предыдущие активные коды номера. В не-продакшене возвращает `debug_code`
  (реальная отправка SMS — за провайдером: SMS.Io / Twilio).
- `POST /api/auth/verify-code` — проверка с лимитом 5 попыток, одноразовость,
  создание пользователя при первом входе по номеру.

## Известные ограничения

- Реальная отправка SMS и email не подключена (нужны ключи провайдера через env).
- Платежи — демо-режим: `POST /api/subscriptions` записывает подписку без внешнего эквайринга.
- Экран анкеты (`/profile`, `/questions`) сохраняет черновик локально; ответы уходят в
  `/api/filters/answers`, но базовые поля профиля на сервер не пишутся.
- Часть таблиц админки и соц-данных наполняется сидом для демо.
